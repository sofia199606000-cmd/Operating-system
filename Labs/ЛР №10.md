## Завдання для попередньої підготовки

### Словник основних англійських термінів 

**Ownership (Власність)** — концепція, згідно з якою кожен об'єкт у файловій системі належить конкретному користувачу (власнику) та певній групі користувачів.

**Permissions (Права доступу)** — набір правил, що визначають рівень доступу (читання, запис, виконання) для власника, групи та всіх інших користувачів системи.

**Read (r) / Читання** — право, що дозволяє відкривати та переглядати вміст файлу, а для каталогів — переглядати список файлів, що в них містяться.

**Write (w) / Запис** — право, що дозволяє змінювати або видаляти вміст файлу, а для каталогів — створювати, видаляти та перейменовувати файли всередині них.

**Execute (x) / Виконання** — право, що дозволяє запускати файл як програму або сценарій, а для каталогів — надає доступ до входу в них (команда cd) та роботи з їхнім вмістом.

**Octal Notation (Вісімкова нотація)** — спосіб представлення прав доступу за допомогою цифр (наприклад, 755), де кожна цифра є сумою значень: 4 (read), 2 (write) та 1 (execute).

**Chown (Change Owner)** — системна утиліта, що використовується для зміни власника та/або групи-власника файлу чи каталогу.

**Chmod (Change Mode)** — команда, що дозволяє змінювати режими доступу до файлів і каталогів, використовуючи символьний (u+x) або числовий (777) формати.

**Root Directory (Кореневий каталог)** — вершина ієрархії файлової системи Linux, яка позначається символом / і містить усі інші файли та підкаталоги.

**Virtual File System (Віртуальна файлова система)** — спеціальні каталоги (наприклад, /proc або /sys), які не існують на фізичному диску, а генеруються ядром у пам'яті для відображення системної інформації та стану процесів.

## Відповіді на наступні запитання:

1. Яке призначення команди id?

Команда id використовується для виведення детальної інформації про ідентифікатори користувача та груп для конкретного облікового запису в системі Linux. Вона відображає унікальний числовий ідентифікатор користувача (UID), ідентифікатор його основної групи (GID), а також список усіх додаткових груп, до яких входить цей користувач. Якщо запустити команду без аргументів, вона покаже дані для поточного користувача, а якщо вказати ім'я (наприклад, id student), вона надасть інформацію про вказаний обліковий запис, що є критично важливим для перевірки прав доступу під час адміністрування.

2. Як переглянути які права доступу має власник файлу?

Для перегляду прав доступу власника найчастіше використовується команда ls з прапорцем -l (long format). У виведенні цієї команди перший стовпець містить рядок із десяти символів, де символи з другого по четвертий (наприклад, rwx) вказують на права саме власника файлу: r — читання, w — запис, x — виконання. Також можна скористатися командою stat, яка надає більш детальну інформацію про файл, включаючи права доступу як у символьному вигляді, так і у вісімковому (числовому) форматі, чітко розмежовуючи права для власника, групи та інших.

3. Як змінити власника групи?

Змінити групу-власника файлу або каталогу можна двома основними способами: за допомогою спеціалізованої команди chgrp (наприклад, chgrp developers file.txt) або за допомогою універсальної команди chown, використовуючи синтаксис із двокрапкою (наприклад, chown :developers file.txt). Обидві команди зазвичай потребують прав суперкористувача (sudo), якщо ви не є власником файлу або не входите до цільової групи. Це дозволяє гнучко керувати спільним доступом команди до певних проектів або системних ресурсів.

4. Як можна переглянути у терміналі який тип поточного файлу? Наведіть приклади для різних типів файлів

 Найкращим способом визначити тип файлу є команда file, яка аналізує вміст файлу (його "магічні числа"), а не лише розширення. Наприклад, для текстового документа команда виведе ASCII text, для скрипта — Bourne-Again shell script executable, а для порожнього файлу — empty. Також можна використовувати ls -l, де перший символ рядка прав вказує на тип: дефіс (-) означає звичайний файл, буква d — директорію (каталог), l — символічне посилання (link), а c або b — спеціальні файли пристроїв.
 
5. Для чого використовуються дозволи Setuid та Setgid?

Спеціальні дозволи Setuid (SUID) та Setgid (SGID) використовуються для розширення стандартної моделі безпеки Linux. Біт SUID, встановлений на виконуваний файл, дозволяє звичайному користувачу запускати цю програму з правами її власника (зазвичай root), що необхідно для таких операцій, як зміна пароля (passwd). Біт SGID на виконуваних файлах діє аналогічно для прав групи, а при встановленні на каталог він гарантує, що всі нові файли, створені всередині, автоматично успадкують групу-власника цього каталогу, що значно спрощує спільну роботу групи користувачів над спільними даними.
   
6. Для чого в системі потрібен так званий “липкий біт” (Sticky Bit). Наведіть приклади коли цей дозвіл доцільно використовувати.

“Липкий біт” (Sticky Bit) — це спеціальний атрибут прав доступу до каталогу, який обмежує право на видалення або перейменування файлів всередині нього. Навіть якщо каталог має права на запис для всіх (777), встановлений Sticky Bit дозволяє видаляти файли тільки власнику цього файлу, власнику каталогу або суперкористувачу. Найбільш доцільно використовувати цей дозвіл у спільних тимчасових директоріях, таких як /tmp або /var/tmp, щоб запобігти ситуаціям, коли один користувач може випадково або навмисно видалити тимчасові дані іншого користувача в спільному просторі.

## Відповіді на контрольні запитання:

1. Наведіть приклади зміни прав доступу символічним методом (Symbolic Method)?
 
 Символьний метод використовує літери для позначення категорій користувачів та оператори для зміни прав. Наприклад, команда chmod u+x file додає власнику право на виконання, chmod g-w file забирає у групи право на запис, а chmod o=r file встановлює для всіх інших користувачів виключно право на читання. Також можна змінювати права для декількох категорій одночасно, наприклад, chmod ug+rw file надасть права на читання та запис і власнику, і групі.
 
2. Наведіть приклади зміни прав доступу числовим методом (numeric method, octal method)?

Числовий метод базується на сумі значень: 4 (читання), 2 (запис) та 1 (виконання). Наприклад, команда chmod 755 file встановлює повні права (7) для власника та права на читання й виконання (5) для групи та інших. Команда chmod 644 file є стандартною для документів, оскільки дає власнику право на читання й запис (6), а всім іншим — лише на читання (4). Для повної заборони доступу всім, крім власника, використовується chmod 700 directory.

3. Яке призначення команди umask?

Команда umask (user file-creation mask) призначена для встановлення маски, яка автоматично обмежує права доступу для нових файлів та каталогів у момент їх створення. Вона працює за принципом віднімання (або логічного заперечення) вказаних у масці бітів від максимально можливих прав (зазвичай 666 для файлів та 777 для папок). Наприклад, якщо umask дорівнює 022, то нові файли отримають права 644, що запобігає можливості запису в них будь-кому, крім власника.

4. Порівняйте жорсткі та символічні посилання?

Жорстке посилання (Hard Link) — це додаткове ім'я, яке вказує на той самий індексний дескриптор (inode) на диску, що й оригінал; воно не може посилатися на каталоги або файли в іншій файловій системі. Символічне посилання (Symbolic/Soft Link) — це окремий файл, який містить шлях до оригінального файлу (як ярлик у Windows); воно може вказувати на будь-який об'єкт, навіть на іншій файловій системі або на каталог, проте стає недійсним, якщо оригінал перемістити або видалити.

5. Чи можна виконати файл, для якого є права на виконання, але не встановлені права на читання (--x)? Поясніть.

Для скомпільованих бінарних файлів відповідь — так, операційна система може завантажити та виконати код без необхідності читання його вмісту користувачем. Проте для скриптів (Bash, Python тощо) це неможливо, оскільки інтерпретатору потрібно спочатку прочитати текст сценарію, щоб його виконати. У випадку каталогів право --x дозволяє увійти в нього та отримати доступ до відомих файлів, але забороняє перегляд списку всіх файлів у ньому.

6. Якщо ми змінюємо права доступу та дозволи в поточній сесії чи будуть вони збережені в наступній?.

Так, права доступу в Linux є атрибутами самої файлової системи та зберігаються безпосередньо в метаданих файлу (inode) на диску. Зміни, внесені за допомогою chmod, chown або chgrp, залишаються чинними після завершення сесії, перезавантаження системи або перемонтування диска, поки вони не будуть змінені користувачем знову вручну.

7. Чи є якийсь шаблон, яким система користується щодо прав та доступів при створенні нових файлів. Як можна змінити права дозволу за замовчуванням?

Так, таким шаблоном є системна маска umask. За замовчуванням більшість систем встановлюють права 666 для файлів та 777 для каталогів, а потім застосовують umask (наприклад, 0022). Змінити це значення можна, виконавши команду umask з новим цифровим значенням у терміналі. Щоб зміни стали постійними для користувача, команду umask слід додати до конфігураційного файлу оболонки, наприклад, у .bashrc або .profile.

8. Яким чином можна створити жорстке посилання? В яких ситуаціях їх доцільно використовувати?

Жорстке посилання створюється командою ln [оригінал] [посилання]. Їх доцільно використовувати для створення резервних копій або дзеркал важливих файлів у межах одного розділу, оскільки вони не займають додаткового місця і файл залишається доступним, поки існує хоча б одне посилання на нього. Також вони корисні для запобігання випадковому видаленню даних, оскільки видалення оригінального імені не знищує дані, якщо є жорстке посилання.

9. Яким чином можна створити символічне посилання? В яких ситуаціях їх доцільно використовувати?

Символічне посилання створюється командою ln -s [шлях_до_оригіналу] [назва_посилання]. Їх доцільно використовувати для створення ярликів до програм, посилань на файли в інших розділах диска, структурування бібліотек або швидкого доступу до глибоко вкладених папок. Також вони незамінні при роботі з версіями програмного забезпечення, де посилання python може вказувати на конкретну версію python3.10.

10. Уявіть, що програмі потрібно створити одноразовий тимчасовий файл, який більше ніколи не знадобиться після закриття програми. Який правильний каталог для створення цього файлу?

Найбільш правильним місцем для створення тимчасових файлів є каталог /tmp. Згідно зі стандартами Linux, цей каталог доступний для запису всім користувачам, а його вміст автоматично очищується при перезавантаженні системи. Для файлів, які мають зберігатися між перезавантаженнями, але все одно є тимчасовими, використовується каталог /var/tmp.

11. Є файл оригінал та для нього створено два посилання \- символічне та жорстке. Що відбудеться з іншими файлами, якщо видалити:  
- файл оригінал - жорстке посилання залишиться робочим і буде містити всі дані файлу; символічне посилання стане "битим" (зламаним) і вказуватиме на неіснуючий шлях.
- символічне посилання - оригінальний файл і жорстке посилання залишаться без жодних змін.
- жорстке посилання - оригінальний файл та символічне посилання залишаться без змін; дані будуть видалені з диска лише тоді, коли буде видалено останнє жорстке посилання (включаючи оригінальне ім'я).
