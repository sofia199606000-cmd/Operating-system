### Словник основних англійських термінів

**User Account** — A unique identity used by a person to log into a Linux system, which defines their files, settings, and level of access.

**Superuser (Root)** — The administrative account in Linux that has absolute control over the system, with the power to modify any file and execute any command.

**Group** — A logical collection of users who share common access rights to specific files, directories, or system resources.

**Bash (Bourne Again SHell)** — A command-line interpreter and scripting language that serves as the interface between the user and the Linux kernel.

**Permissions** — A set of attributes attached to files and directories that determine who can read (r), write (w), or execute (x) them.

**Sudo (superuser do)** — A command that allows a permitted user to execute programs with the security privileges of another user, usually the superuser.

**Home Directory** — A specific folder (usually located in /home/) dedicated to a particular user for storing their personal files and configuration settings.

**Authentication** — The security process of verifying the identity of a user, typically by requiring a username and a password.

**UID (User Identifier)** — A unique numerical value assigned by the Linux system to each user to track ownership and manage access control.

**GID (Group Identifier)** — A unique numerical value assigned to each group in Linux, used to manage permissions for multiple users simultaneously.

## Відповіді на наступні запитання:

1. Розкрийте поняття UPG, коли їх доцільно використовувати?

Концепція UPG (User Private Groups) — це стратегія управління користувачами в Linux, згідно з якою для кожного нового користувача автоматично створюється однойменна група, де цей користувач є єдиним учасником. Це дозволяє уникнути проблем із безпекою, що виникали в старих UNIX-системах, де всі користувачі за замовчуванням належали до однієї загальної групи (наприклад, users), що часто призводило до небажаного доступу до чужих файлів. Використовувати UPG доцільно в багатокористувацьких середовищах, оскільки це робить роботу з файлами більш безпечною та гнучкою: користувач може встановлювати права доступу для своєї приватної групи, не впливаючи на інших, а при необхідності спільної роботи — просто додавати потрібних колег до цієї групи або використовувати механізм setgid на спільних папках.

2. Якими командами можна створити групи користувачів? Наведіть приклади

Для створення груп користувачів у Linux найчастіше використовується команда groupadd. Вона дозволяє додати нову групу до системи, вказавши її назву та, за потреби, специфічні параметри, як-от ідентифікатор групи (GID). Наприклад, команда sudo groupadd developers створить групу з назвою «developers» з наступним вільним номером GID, а команда sudo groupadd -g 1500 managers створить групу «managers» із чітко визначеним ідентифікатором 1500. У деяких дистрибутивах також доступний більш високорівневий скрипт addgroup, який працює аналогічно, але може бути більш інтерактивним.

3. Якими командами можна змінити налаштування груп користувачів? Наведіть приклади 

Зміна налаштувань уже існуючих груп здійснюється за допомогою команди groupmod. Вона дозволяє перейменувати групу або змінити її цифровий ідентифікатор. Наприклад, щоб змінити назву групи з «developers» на «engineers», слід виконати команду sudo groupmod -n engineers developers, а щоб змінити GID групи «engineers» на 2000, використовується команда sudo groupmod -g 2000 engineers. Крім того, для управління складом групи (додавання або видалення користувачів) часто використовують команду gpasswd, наприклад, sudo gpasswd -a user1 developers додасть користувача user1 до групи, а sudo gpasswd -d user1 developers — видалить його з неї. Також для керування паролями груп (що зараз використовується рідко) та адміністраторами груп можна застосовувати той самий інструмент gpasswd.

## Відповіді на контрольні запитання:

1. Чому в конфігураційних файлах паролі не зберігається в явному вигляді?

Паролі не зберігаються у відкритому вигляді з міркувань безпеки. Якби паролі були записані текстом, будь-який користувач або зловмисник, що отримав доступ до файлів конфігурації, міг би їх прочитати. Замість цього використовується хешування — одностороннє математичне перетворення. Система порівнює хеш введеного пароля з тим, що зберігається в системі, не знаючи самого пароля.

2. Чому не рекомендується виконувати повсякденні операції, використовуючи обліковий запис root?

 Використання root для звичайних завдань є небезпечним, оскільки суперкористувач має необмежені права. Будь-яка помилка в команді (наприклад, зайвий пробіл у rm -rf) може призвести до повного видалення системи без попередження. Також будь-яка програма (або вірус), запущена від імені root, отримує повний контроль над ОС.
 
3. У чому відмінність механізмів отримання особливих привілеїв su і sudo?

Команда su (substitute user) вимагає пароль користувача root і створює нову оболонку від імені суперкористувача. Команда sudo (superuser do) дозволяє виконати конкретну команду з привілеями root, використовуючи власний пароль користувача. sudo вважається безпечнішим, оскільки дозволяє гнучко налаштовувати права та веде журнал дій.

4. Чому домашній каталог користувача root не розміщено в каталозі /home?

Каталог /root винесено окремо від /home, щоб адміністратор мав доступ до системи та інструментів відновлення, навіть якщо розділ, де знаходяться домашні каталоги звичайних користувачів (часто це окремий диск або розділ), не вдалося змонтувати через помилку або збій.

5. Для чого використовується команда getent?

Команда getent (get entries) використовується для отримання записів із системних баз даних (passwd, group, hosts тощо). На відміну від простого читання файлу (як cat /etc/passwd), getent показує дані не лише з локальних файлів, а й із мережевих служб (наприклад, LDAP), якщо вони налаштовані.

6. Як можна змінити пароль користувача?

Для цього використовується команда passwd. Звичайний користувач може змінити свій пароль, ввівши просто passwd (система запитає старий пароль, а потім новий). Суперкористувач може змінити пароль будь-якого користувача командою sudo passwd [username], не знаючи старого пароля.

7. Яким чином можна видалити існуючі групи користувачів? Чи залишиться інформація про них десь у системі?

Групи видаляються командою groupdel . Після виконання інформація про групу видаляється з файлу /etc/group. Проте файли, що належали цій групі, залишаться в системі: замість імені групи в їхніх атрибутах буде відображатися цифровий ідентифікатор (GID) видаленої групи.

8. Яке призначення команди chage?

Команда chage (change age) призначена для управління параметрами застарівання паролів. Вона дозволяє встановити дату закінчення терміну дії пароля, мінімальну та максимальну кількість днів між змінами пароля, а також налаштувати попередження користувача про необхідність зміни пароля.

9. Які параметри команди usermod ви вважаєте найбільш використовуваними?

Найчастіше використовуються:

-aG — додавання користувача до додаткової групи (без видалення з поточних);

-l — зміна імені користувача (логіна);

-d — зміна шляху до домашнього каталогу;

-L та -U — блокування (Lock) та розблокування (Unlock) облікового запису.
