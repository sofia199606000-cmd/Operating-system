## Завдання для попередньої підготовки

### Словник основних англійських термінів 

1. Kernel (Ядро) — головна частина операційної системи, яка виступає посередником між апаратним забезпеченням (залізом) та програмами.

2. Process ID / PID (Ідентифікатор процесу) — унікальний цифровий номер, який система присвоює кожному запущеному процесу для його відстеження.

3. Load Average (Середнє навантаження) — показник, що відображає стан черги процесів до процесора за останні 1, 5 та 15 хвилин.

4. FHS (Filesystem Hierarchy Standard) — стандарт, який визначає, у яких папках Linux мають зберігатися певні типи файлів (наприклад, конфігурації в /etc, а логи у /var/log).

5. Pseudo-filesystem (Псевдофайлова система) — віртуальна файлова система (як /proc або /sys), яка не існує на диску, а створюється ядром в оперативній пам'яті для доступу до системних даних.

6. Mount Point (Точка монтування) — каталог (папка) у файловій системі, до якого "підключається" розділ диска або зовнішній пристрій.

7. DHCP (Dynamic Host Configuration Protocol) — мережевий протокол, який дозволяє комп'ютеру автоматично отримувати IP-адресу та інші налаштування від роутера або сервера.

8. Default Gateway (Основний шлюз) — IP-адреса мережевого пристрою (зазвичай роутера), куди комп'ютер відправляє всі пакети, призначені для зовнішніх мереж або Інтернету.

9. Routing Table (Таблиця маршрутизації) — набір правил у системі, що визначають, через який інтерфейс і куди саме мають передаватися мережеві дані.

10. Socket (Сокет) — програмний вузол для обміну даними, що складається з IP-адреси та номера порту (наприклад, 192.168.1.5:80).

## Відповіді на наступні запитання:

1. Розкрийте поняття “псевдо файлової системи”, для чого воно потрібно системі?

Псевдофайлова система — це особливий тип файлової системи в Linux, яка не існує фізично на жорсткому диску, а створюється ядром операційної системи безпосередньо в оперативній пам'яті під час завантаження. Вона виступає як інтерфейс (або «вікно»), через який користувач або прикладні програми можуть взаємодіяти з ядром. Головне призначення такої системи полягає в наданні зручного доступу до внутрішніх структур даних ядра, стану запущених процесів та інформації про апаратне забезпечення за допомогою звичайних файлових операцій, таких як читання або запис. Це дозволяє уникнути написання складних низькорівневих запитів до пам'яті, замінюючи їх звичними командами для роботи з текстом.

2. Чому користувачі не так часто звертаються на пряму до каталогу /proc, яким чином з нього можна 
отримати інформацію?

Користувачі зазвичай не звертаються до каталогу /proc напряму через те, що дані в ньому зберігаються у сирому, неструктурованому текстовому форматі, який важко сприймати людині без спеціальної підготовки. Замість прямого читання файлів системні адміністратори використовують спеціалізовані утиліти, такі як top, ps, free або uptime. Ці команди автоматично зчитують необхідні файли з /proc, обробляють отримані дані та виводять їх у зручному, табличному або графічному вигляді. Проте за потреби отримати інформацію з цього каталогу можна і напряму, використовуючи стандартні команди перегляду тексту, наприклад, cat /proc/cpuinfo для отримання характеристик процесора.

3. *Яке призначення файлів /proc/cmdline, /proc/meminfo та /proc/modules?

Ці три файли є ключовими джерелами системної інформації в реальному часі. Файл /proc/cmdline містить повний рядок параметрів, які були передані ядру завантажувачем (наприклад, GRUB) у момент старту системи; це допомагає зрозуміти, з якими опціями завантажилася ОС. Файл /proc/meminfo надає детальний звіт про використання оперативної пам'яті, включаючи загальний обсяг, вільну пам'ять, буфери та кеш. Файл /proc/modules відображає список усіх завантажених у даний момент модулів ядра (драйверів), вказуючи їх розмір та залежності, що важливо для діагностики роботи обладнання.

4. *Яке призначення команди free?

Команда free призначена для швидкого та наочного моніторингу стану оперативної пам'яті (RAM) та розділу підкачки (Swap) у системі. Вона аналізує дані з файлу /proc/meminfo і виводить результати у зручних одиницях виміру (байтах, мегабайтах або гігабайтах). За допомогою цієї команди системний адміністратор може миттєво оцінити, скільки ресурсів пам'яті споживають запущені додатки, яка частина зарезервована системою під кешування та чи не вичерпано ліміт пам'яті, що може призвести до сповільнення роботи комп'ютера.

5. *Для чого потрібні лог-файли, наведіть приклади їх застосування?

Лог-файли (або системні журнали) відіграють критичну роль у забезпеченні стабільності та безпеки системи, оскільки вони автоматично фіксують усі важливі події, що відбуваються в ОС та додатках. Головне їх призначення — надання хронологічної історії дій для подальшого аналізу. Наприклад, системні логи допомагають виявити причину збою сервісу, аналізуючи повідомлення про помилки. У сфері безпеки логи використовуються для виявлення спроб несанкціонованого доступу (файл /var/log/auth.log), а розробники програмного забезпечення використовують логування для відстеження коректності виконання коду та взаємодії компонентів системи.

6. **Яке призначення файлу /var/log/dmesg?

Файл /var/log/dmesg містить текстові повідомлення, які генеруються ядром системи під час процесу завантаження. У цьому журналі фіксується інформація про ініціалізацію апаратних компонентів: виявлення процесора, обсягу пам'яті, підключення дисків та мережевих адаптерів. Перегляд цього файлу є першим кроком при вирішенні проблем із «залізом», оскільки саме тут відображаються помилки драйверів або конфлікти пристроїв, що виникли ще до того, як користувач увійшов у систему.

7. **Для чого розроблено FHS?

Стандарт ієрархії файлової системи (FHS) був розроблений для того, щоб встановити єдині правила розміщення файлів та каталогів у всіх дистрибутивах Linux. Це необхідно для забезпечення сумісності програмного забезпечення та спрощення адміністрування. Завдяки FHS розробники знають, куди саме потрібно встановлювати виконувані файли чи бібліотеки, а користувачі та адміністратори завжди можуть передбачити, де знайти конфігураційні файли (у /etc), тимчасові дані (у /tmp) або змінні дані журналів (у /var/log), незалежно від конкретної версії Linux.

8. **Які основні команди є у Linux для перегляду та конфігурації мережі

Для перегляду та налаштування мережевих параметрів у Linux існують два основні набори інструментів. До класичного набору належать команди ifconfig (перегляд інтерфейсів та IP-адрес), route (керування таблицею маршрутизації) та netstat (аналіз активних мережевих з'єднань). Однак у сучасних дистрибутивах ці команди вважаються застарілими, і їм на зміну прийшов потужніший пакет iproute2. Він включає команду ip з різними параметрами (наприклад, ip addr для адрес, ip route для маршрутів) та утиліту ss, яка призначена для отримання детальної статистики сокетів і працює швидше за свою попередницю.

- **опишіть можливості команди dig та наведіть приклади;

  dig (Domain Information Groper) — це потужний інструмент для діагностики DNS. Він дозволяє запитувати інформацію про доменні імена у DNS-серверів.

Запит до конкретного DNS-сервера (наприклад, Google DNS): dig @8.8.8.8 google.com

- **опишіть можливості команди netstat та наведіть приклади.

netstat (network statistics) — утиліта для моніторингу мережевих з'єднань, таблиць маршрутизації та статистики інтерфейсів.

Призначення: пошук програм, що займають певні порти, перевірка активних з'єднань з інтернетом, діагностика мережевих помилок.

Приклади:

Відобразити всі активні з'єднання (TCP та UDP): netstat -a

Показати порти, які "слухають" (чекають на підключення): netstat -l

Вивести цифрові адреси замість імен (швидше працює): netstat -an

Показати, якій програмі (PID) належить з'єднання (потрібен sudo): sudo netstat -tpln

## Відповіді на контрольні запитання:

1. Як пов'язані між собою команди cat та tac?

 Команди cat та tac є функціональними антонімами, призначеними для виведення вмісту текстових файлів у термінал. Команда cat (скорочення від concatenate) виводить вміст файлу у прямому порядку — від першого рядка до останнього. Команда tac працює рівно навпаки (що відображено навіть у її назві, яка є дзеркальним написанням cat): вона зчитує файл і виводить його рядки у зворотному порядку, починаючи з кінця. Це особливо корисно при аналізі великих лог-файлів, коли адміністратору потрібно спочатку побачити найсвіжіші записи, що знаходяться внизу файлу.
 
2. Що робить команда ss?

Команда ss (socket statistics) — це потужна сучасна утиліта, призначена для дослідження мережевих сокетів і моніторингу активних з'єднань у системі. Вона прийшла на зміну застарілій команді netstat і працює значно швидше, оскільки отримує дані безпосередньо з адресного простору ядра. За допомогою ss можна отримати детальну інформацію про всі типи з'єднань (TCP, UDP, Unix-сокети), дізнатися, які порти відкриті в системі, які процеси їх використовують, а також відстежувати стан передачі пакетів у реальному часі.

3. В чому відмінність між командами ps --forest та pstree?

Обидві команди використовуються для візуалізації ієрархії процесів (зв’язків «батько-нащадок»), проте вони мають різний формат виводу та походження. Команда pstree спеціально розроблена для створення візуального «дерева» процесів, використовуючи символи псевдографіки, що робить структуру дуже наочною та легкою для читання. Команда ps --forest є лише одним із режимів відображення універсальної утиліти ps; вона виводить процеси списком, але додає спеціальні символи (відступи та лінії) перед назвами команд, щоб показати їхню вкладеність. pstree зазвичай компактніша, тоді як ps --forest дозволяє виводити більше додаткових стовпців з даними (PID, власник, споживання пам'яті).

4. *У яких каталогах зберігаються налаштування системи?

Усі глобальні конфігураційні файли та налаштування операційної системи Linux згідно зі стандартом FHS зберігаються в каталозі /etc. Ця директорія містить параметри роботи мережі, облікові записи користувачів, налаштування завантажувача, правила доступу та конфігурації практично всіх встановлених сервісів (наприклад, вебсервера чи бази даних). Окрім загальносистемних налаштувань, існують також індивідуальні налаштування користувачів, які зберігаються у прихованих (крапкових) файлах та папках безпосередньо в домашньому каталозі користувача (/home/username/).

5. *У яких каталогах можна знайти встановлені в системі програми, доступні для користувача?

Виконувані файли стандартних програм та команд, які доступні звичайним користувачам системи, зберігаються переважно у двох каталогах: /bin та /usr/bin. Каталог /bin (binary) історично містив мінімальний набір утиліт, необхідних для роботи системи в однокористувацькому режимі або для відновлення (наприклад, ls, cp, bash). Більшість же прикладних програм, які встановлює користувач пізніше, розміщуються в /usr/bin. У сучасних дистрибутивах ці каталоги часто є посиланнями (symlinks) один на одного для спрощення структури.

6. *У яких каталогах можна знайти встановлені системні програми і програми призначені для виконання суперкористувачем?

 Програми, призначені для системного адміністрування, обслуговування мережі та виконання завдань, що потребують прав суперкористувача (root), зберігаються в каталогах /sbin та /usr/sbin. Літера «s» у назві означає «system» або «superuser». Тут знаходяться утиліти для керування дисками (як-от fdisk), налаштування мережевих інтерфейсів, перезавантаження системи та керування файловими системами. Звичайний користувач може бачити ці файли, але для їх запуску або внесення змін йому знадобляться права sudo.
 
7. **Поясніть призначення команд ping, ifconfig, traceroute.

 Ці три команди є базовим інструментарієм для діагностики мережі. Команда ping використовується для перевірки доступності віддаленого хоста та вимірювання затримки передачі даних (RTT). Команда ifconfig призначена для перегляду та налаштування параметрів локальних мережевих інтерфейсів, таких як IP-адреса, маска підмережі та статус з'єднання. Команда traceroute дозволяє відстежити повний шлях мережевого пакета від вашого комп'ютера до цільового сервера, показуючи всі проміжні вузли (маршрутизатори) та час затримки на кожному з них, що допомагає знайти місце розриву зв'язку.
 
8. **Як називаються мережеві інтерфейси в Linux?

Назви мережевих інтерфейсів у Linux залежать від дистрибутива та способу іменування. Класично інтерфейси іменувалися за типом технології: eth0, eth1 для дротового Ethernet або wlan0 для Wi-Fi. Проте в сучасних системах (наприклад, Ubuntu або Debian) використовується «передбачуване іменування» (Predictable Network Interface Names), де назва залежить від фізичного розташування пристрою на шині або в слоті материнської плати. Такі назви виглядають як enp0s3 (Ethernet на шині PCI 0, слот 3) або wlp2s0. Також у кожній системі обов'язково присутній віртуальний інтерфейс lo (loopback), який використовується для звернення комп'ютера до самого себе.

9. **Як за допомогою команди ifconfig вивести параметри тільки одного мережевого інтерфейсу (наприклад, eth1), а не всіх?

За замовчуванням команда ifconfig виводить інформацію про всі активні мережеві пристрої в системі. Для того, щоб вивести параметри лише одного конкретного інтерфейсу (наприклад, eth1 або enp0s3), необхідно вказати його назву як аргумент безпосередньо після назви команди. Формат виглядає так: ifconfig eth1. У такому разі система проігнорує всі інші інтерфейси та покаже дані лише для обраного адаптера, включаючи його IP-адресу, MAC-адресу, кількість переданих пакетів та наявність помилок.
